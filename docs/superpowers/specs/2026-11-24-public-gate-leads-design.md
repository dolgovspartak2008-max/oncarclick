# Публичные заявки во втором Telegram-боте

## Цель

Сделать `@OnCarClickk_bot` доступным клиентам для подачи заявки на конкретный автомобиль. Служебный основной бот и существующий сайт сохраняют текущее поведение.

## Сценарии

- Владелец второго бота получает прежнее служебное сообщение и заявки с сайта.
- Обычный пользователь видит приветствие, кнопку «Оставить заявку» и ссылку на полный каталог.
- Форма последовательно запрашивает имя, желаемый автомобиль, бюджет и телефон. Телефон можно отправить контактом Telegram или текстом.
- Перед отправкой бот показывает заполненные данные с кнопками подтверждения и отмены.
- Подтверждённая заявка сохраняется в существующей таблице `leads`, после чего все владельцы второго бота получают её карточку.
- Клиент получает подтверждение и кнопку `Открыть каталог` со ссылкой `https://www.oncarclick.com/catalog.html`.
- Telegram ID `944732927` идемпотентно добавляется во владельцы второго бота при проверке вебхука после развёртывания.

## Архитектура и данные

Форма реализуется в `src/server/gate.ts`. Для черновика используется существующий серверный механизм `bot_get_state` / `bot_set_state`; владельцы второго бота не входят в клиентскую форму, поэтому их служебное состояние не затрагивается.

Заявка создаётся существующей функцией `site_add_lead`. Поля `car` и `budget` сохраняются в `comment`, источник — в `page`. Вместо IP для лимита используется SHA-256 от `telegram:<chat_id>` с `BOT_DB_SECRET`; исходный Telegram ID в поле лимита не хранится. Действуют текущие ограничения: до трёх заявок за 10 минут и десяти за сутки, а повтор телефона за 10 минут не создаёт повторное уведомление.

Если второй бот не доставил уведомление владельцам, используется существующая резервная отправка администраторам основного бота. Сохранённая заявка не теряется.

## Валидация и ошибки

- Только личный чат.
- Имя: 2–80 символов; автомобиль: 2–300; бюджет: 1–80; телефон: 10–30, минимум 10 цифр.
- Весь пользовательский текст экранируется перед отправкой в HTML Telegram.
- Кнопки подтверждения работают только для пользователя, которому принадлежит черновик.
- При ошибке сохранения черновик остаётся; бот предлагает повторить.
- При превышении лимита клиент получает понятное сообщение без внутренних деталей.

## Проверка

Тесты покрывают маршрут владельца, публичное приветствие, все шаги формы, контакт Telegram, отмену, подтверждение, сохранение, уведомление владельцев, резервную отправку, лимит и добавление второго администратора. После тестов выполняются lint, typecheck, production build и проверка развёрнутого бота.
